### ImportExportSystem  (DIG-CAREFUL)
- 
  - lead: HIGH (reasoning-tier) -- abi.encodePacked hash-collision on adjacent dynamic arrays. ImportExportSystem.sol:100 verifySignature does keccak256(abi.encodePacked(player, itemIds, itemAmounts, nonce)). itemIds and itemAmounts are two adjacent unbounded uint256[] with no length prefix/separator, while player (head) and nonce (32B tail) are fixed. The concatenated middle blob ids||amts can be RE-PARTITIONED at a different boundary into (ids',amts') that yields the SAME digest and thus the SAME valid signature -- so one signer-authorized export can be replayed by the player with a different (itemIds,itemAmounts) split passed to _exportItemsFromGame->gameItems.mint (line 268), e.g. shifting a large value between an amount-slot and an item-id slot or changing which item gets the big amount. Exploitable IFF the off-chain signer ever signs multi-element (len>1) batches; if it only ever signs single equal-length arrays the only re-split is into empty arrays (no mint). Asset-dup / over-mint primitive on a permissionless live entrypoint.  [] (?)
  - lead: MEDIUM (reasoning-tier) -- signature not bound to chainid or address(this) => cross-deployment/cross-system replay. ImportExportSystem.sol:100-101 omits block.chainid and the contract address from the digest. Nonce consumption is tracked per-THIS-contract's DataStore (line 300-308), so a signature consumed here is NOT marked used on any sibling system / future redeploy / other chain that reuses the same signer key and the same (player,ids,amts,nonce) scheme -> the same signed export can be replayed there for a second on-chain mint (double-issue). Exploitable IFF the signer key is reused across deployments/chains; single-deployment unique key = safe.  [] (?)
  - lead: LOW / by-design note -- export license is a balance check, not a burn. playerCanExportItem (line 112-124) gates export on gameItemContract.balanceOf(player, exportLicenseId) > 0; the license is never consumed, so one license NFT permits unlimited repeated exports of the licensed item (still gated by signer + cooldown). Intended (license=permission, signer caps amounts), flagged only as part of the trust surface.  [] (?)
  - lead: DISMISSED FP -- exportItemsFromGame writes the cooldown timestamp (line 69) BEFORE _confirmVerifyAndUseSignature (line 71); on an invalid signature the whole tx reverts and the write rolls back, so there is no premature-state-write bug. Also recon's signature/ecrecover detector returned 0 because the code uses SignatureChecker.isValidSignatureNow, not raw ecrecover -- a detector blind spot, not a clean bill of health.  [] (?)

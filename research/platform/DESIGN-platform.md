## Problem Statement
~30 CLI-тулов + 24/7 радары производят богатое состояние (registry: 92 триаженных таргета;
ledger вердиктов; QUEUE/FRESH-DEPLOY/FRESH-FEED/SECRETS радары; repos.json = 44 watched-репо;
calibration findings + calibrate precision/recall), но оно **разбросано по JSON+markdown**. Нет единого
ВИЗУАЛЬНОГО вида пайплайна (по стадиям) и нет унифицированного ВЗАИМОДЕЙСТВИЯ (только терминал).

## What Makes This Cool (the win)
Одно место, где видно весь хант (kanban таргетов по стадиям + свежесть радаров + findings + метрики)
И где можно ДЁРГАТЬ лабу как инструменты из любого клиента (Claude / claude.ai / телефон) через MCP.

## Constraints
- Solo-хобби (egor + Claude), без дедлайнов; берём правильное даже если долго.
- **Архитектурно расширяемо** — новый тул подключается без переписывания фронтов.
- **Источник правды остаётся в git-файлах**; `lab-state.json` — read-through ПРОЕКЦИЯ, не БД.
- White-hat: `lab-state.json` агрегирует ВСЕ parked exploitable-лиды на живых контрактах →
  это самый чувствительный файл проекта. Репо приватно (ок сегодня); наружу — только sanitized.
- ASCII-дружелюбный вывод; stdlib-first (с одним явным исключением — см. MCP-слой).

## Premises (agreed)
1. Git-файлы = источник правды. `lab-state.json` — **read-through cache**: НИКОГДА не редактируется
   руками и не пишется напрямую; мутации идут в НИЖНИЙ стор (ledger/watchlist) → потом re-derive.
2. Это DX/observability, **не finding-rate** — багов не прибавит.
3. Главная сложность и ценность — **КОНТРАКТ состояния** (явный JOIN над производными кэшами).
4. MCP и Web — два фронта над ОДНИМ ядром (`labcore`).

## Approaches Considered
- **A) Минимальный статичный дашборд** над сырыми JSON. S/Low. Дрейфует на каждый тул, нет MCP. Отклонено.
- **B) 3-слойная (контракт → labcore → MCP + web). CHOSEN.** L (инкрементами)/Low-Med. Контракт = шов
  расширяемости; оба фронта над одним ядром; тестируемо.
- **C) MCP-only.** M/Low. Нет визуального at-a-glance, который egor явно хочет. Отклонено как единственный путь.

## Recommended Approach — B

```
  Layer 0  CONTRACT   toolkit/labstate.py -> monitor/lab-state.json   (read-through projection; JOIN над кэшами)
  Layer 1  labcore    toolkit/labcore.py   операции: pipeline()/targets()/next_dig()/record_verdict()/
                                            radars()/findings()/metrics(). Pure, tested. Мутации -> нижний стор -> re-derive.
  Layer 2a MCP        toolkit/lab_mcp.py   labcore как MCP-инструменты (stdio; http+auth позже)
  Layer 2b Web        web/index.html       статичный, READ-ONLY над lab-state.json (kanban+радары+findings+метрики)
  Layer 1.5 Bridge    toolkit/lab_http.py  крошечный stdlib localhost HTTP->labcore (даёт web POST-мутации; путь к remote)
```

### lab-state.json — схема v1 (типизированные массивы, НЕ один lossy enum)
```
{
  "version": 1, "generated": "<date>",
  "targets":  [ {id, name, zones[], chains[], fork_base, status, owasp[], sensitivity,
                 verdicts[], firstseen, lastupdated, sources[]} ],
  "findings": [ {id, target, sev_claimed, sev_awarded, status, bounty_received, ...} ],  // ПОЛНЫЙ lifecycle
  "parked":   [ {id, title, target, fire_means, where} ],                                 // гипотезы, своя форма
  "radars":   { queue:{n, fresh_items[]}, freshdeploy:{n}, freshfeed:{n},
                secrets:{repos, leaks}, impl_upgrades:{n}, bounty_launches:{n} },
  "repos":    [ {slug, protocol, chain, source, bounty, head_sha, leaks} ],               // JOIN
  "metrics":  { precision:{tp,fp,value|null}, recall:{caught,total,value} }               // pure-fns, текст
}
```
- `findings` AUTHORITATIVE = `toolkit/calibration.json findings[]` (sev_claimed/sev_awarded/status
  drafted→accepted/disputed/duplicate/bounty_received) — это РЕАЛЬНЫЙ KPI проекта. Не сливать с parked/ledger.
- `parked` = `monitor/watchlist.json findings[]` (другая форма: `fire_means`/`check`, без severity) — отдельно.
- ledger-вердикты `real` всплывают как `targets[].verdicts` (не отдельный finding-стор).
- `metrics` = вызвать `calibrate.precision_stats` / `recall_stats` (ЧИСТЫЕ функции, НЕ файл). **`hitrate` УДАЛЁН**
  (кода нет: QUEUE→finding линковки не существует — спецануть отдельно, если захотим).
- `sensitivity` per-target → делает sanitized-проекцию (Inc 5) МЕХАНИЧЕСКОЙ.

### field → source MAP (контракт = явный JOIN над ПРОИЗВОДНЫМИ кэшами; labstate.py НАД деривёрами, не дублирует их)
| Поле | Источник | Заметка |
|---|---|---|
| `targets` | `monitor/registry.json` (уже derived из ledger через registry.py) | читаем кэш, НЕ re-парсим ledger |
| `targets[].status` | registry: **`REAL/DIG/PARK/CLEAN/SKIP`** (UPPERCASE) | сохранить ВСЕ 5 вкл. `SKIP` (61/92); `sourced/triaged` НЕ существуют — не выдумывать |
| `targets[].verdicts` | `toolkit/triage-ledger.json` (JOIN по norm_key) | |
| `findings` | `toolkit/calibration.json findings[]` | полный lifecycle |
| `parked` | `monitor/watchlist.json findings[]` | |
| `radars.*.n` (counts) | `monitor/radar-seen.json` / `freshfeed-seen.json` / `deployers.json` / `repos.json` | durable counts тут |
| `radars.*.fresh_items` | `hunts/_radar/*.md` | свежая ДЕЛЬТА живёт только в .md (транзиентно), парсим оттуда |
| `repos` | `monitor/repos.json` × `monitor/secrets-seen.json` (JOIN по slug) | `head_sha`/`leaks(=keys[])` из seen, не из repos.json |
| `metrics` | `calibrate.precision_stats()` + `recall_stats()` (import, pure) | ничего не персистится — вызвать |

## Open Questions
- **Web-стек:** vanilla single-file (рекомендую, zero-maint).
- **MCP-хостинг:** локальный stdio сейчас; http+auth позже — ТОЛЬКО при выполненном precondition «репо/данные
  приватны» (sensitivity-поле обязательно). Доступ с телефона = Inc 5.
- **stdlib-first честно:** Layer 2a (MCP) — взять Python MCP SDK как ЕДИНСТВЕННУЮ внешнюю зависимость
  (hand-roll JSON-RPC handshake/framing — реальная работа); stdlib-first остаётся для всех остальных слоёв.

## Success Criteria
- `lab-state.json` — ОДНА read-through правда; состояние любого тула видно через неё (включая `SKIP`).
- `brief.py` ЧИТАЕТ `lab-state.json` (а не свой второй md-парсер) → доказывает контракт, убирает дрейф.
- Одна web-страница показывает весь хант at-a-glance.
- Я (Claude) веду пайплайн через MCP-инструменты; мутации идут в нижний стор → re-derive.
- **Новый тул требует НОЛЬ изменений во фронтах** (главный тест расширяемости).
- Golden-тесты на контракт (схема + field→source) + labcore.

## Distribution Plan
Local-first: stdio MCP (регистрируется в Claude Code) + локальный web (`python -m http.server`; web читает
`lab-state.json` по http, НЕ file:// — иначе CORS). Actions генерит `lab-state.json` после радаров и коммитит
его — **`git add -f monitor/lab-state.json`** (monitor/ в .gitignore, иначе silently пропустится). Опц. позже:
hosted MCP (http+auth) для remote/телефона, gated на приватности + sensitivity.

## Dependencies
Переиспользует: `registry.json` (cartography+query), `triage-ledger.json`, `calibration.json` +
`calibrate.precision_stats/recall_stats` (pure), `watchlist.json`, `repos.json`, `secrets-seen.json`,
`radar-seen.json`/`freshfeed-seen.json`/`deployers.json`, `hunts/_radar/*.md`. MCP — Python MCP SDK (1 dep).
Ничего не ломаем — слой НАД деривёрами.

## Next Steps (инкременты — пере-секвенс: визуал РАНЬШЕ, т.к. это и есть боль egor'а)
1. **Inc 1 — контракт.** `labstate.py` (JOIN по карте выше) → `monitor/lab-state.json` + golden-тесты (схема +
   каждый field→source). Доказать контракт: **`brief.py` начинает читать `lab-state.json`**. CI: `git add -f`.
2. **Inc 2 — web-дашборд (READ-ONLY)** над `lab-state.json`: kanban по `REAL/DIG/PARK/CLEAN/SKIP` + radar-панель
   + findings(lifecycle) + parked + метрики ТЕКСТОМ (3 числа, БЕЗ чарта — датасет = 3 finding/1 recall, тренда нет).
   Это закрывает заявленную боль «визуально ничего не видно» раньше всего.
3. **Inc 3 — labcore + MCP (stdio).** Операции над состоянием + мутации (record_verdict пишет ledger → re-derive).
   Зарегистрировать в Claude Code. Даёт мне/claude.ai вести пайплайн инструментами.
4. **Inc 4 — localhost HTTP-bridge** (`lab_http.py`, stdlib) → web POST'ит мутации через labcore (read-only web
   становится интерактивным). Тот же bridge = путь к remote.
5. **Inc 5 (опц., позже) — hosted/remote** (http-MCP+auth ИЛИ sanitized публичный снапшот для телефона),
   gated на precondition приватности + механической sanitize по `sensitivity`.

## Reviewer Concerns — resolved
Адверсариальное ревью (7/10) подняло: (1) findings/metrics привязаны к реальным источникам, hitrate удалён;
(2) web-мутация через stdio-MCP невозможна → Inc-2 web READ-ONLY, мутации через HTTP-bridge (Inc 4);
(3) контракт = явный JOIN + field→source карта (вкл. `SKIP`, `git add -f`, repos×seen JOIN, radar counts из
*-seen.json а delta из .md). Все три + вторичные (read-through cache, brief.py consumes contract, метрики
текстом не чартом, SDK-dep честно) — внесены выше.

## What I noticed about how you think
- «Архитектурно расширяемую штуку делаем» + «можно браться за сложное» → готовность платить вперёд за
  ШОВ (контракт), а не за быстрый UI. Поэтому B и контракт-первым.
- Ты сам связал «визуально ничего» с «встроить MCP» → нащупал, что нужен слой ВЗАИМОДЕЙСТВИЯ, не только вид.
- Весь движок шёл «один инкремент за раз» → план = 5 инкрементов, чистый data-слой первым, визуал вторым.
